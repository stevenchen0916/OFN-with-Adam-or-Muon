# 在原有 OFN 实验上补对照（16 核 Slurm）
从 ZIP 解压目录执行。服务器默认复用 $HOME/HeatProject/.venv/bin/python，路径不同时先 export REV_PY=/实际路径/bin/python。作业配置为 T1 分区、16 核、32 GB。首次提交仅运行核心实验。

```bash
unzip OFN_incremental_server16.zip
cd OFN_incremental_server16
sha256sum -c SHA256SUMS > /dev/null
bash revision/submit.sh core
squeue -u "$USER"
```

## 核心实验
每道方程原有的九配置、十种子测试结果保留。热方程使用随包提供、已核对历史结果标识的 90 份最终权重，在同一批 1,000 个新测试输入上评估原模型和新增模型。Burgers 沿用原测试集，并从原公开逐种子表读取已有结果。两个 PDE 分别计算配对交互。

1. 原 Full 和 No-Flow 的 Adam 基础学习率均为 0.001。以此为中心做有限联合搜索，基础学习率取 0.0003、0.001，投影学习率采用该 PDE 两个原架构在验证集选出的投影速率（heat 为 0.001、0.003；Burgers 为 0.0003、0.001）。在同一 2×2 网格上比较双学习率 Adam 和 Muon–Adam。两者只在三个输出投影矩阵使用的更新规则上不同。
2. 对每个架构复用原混合优化器网格中完全匹配的两格。剩余两格及分组 Adam 的四格使用原调参种子 289–291，按 2 万步最后三个验证检查点误差中位数的跨种子均值选率。每个 PDE 共需 36 次新调参。并列时取较小学习率。selection.json 同时记录已有与新增验证分数。报告时需写明这个局部网格是在原实验后设计的，并注明覆盖的候选值。
3. 共同学习率比较预先固定基础学习率 0.001，投影学习率使用该 PDE 原 No-Flow 在验证集选出的速率。该比较只覆盖这一共同设置。另报告分架构局部联合选率的比较。正式训练使用 292–301；匹配原正式设置时复用原模型或原测试结果。即使投影学习率等于基础学习率，也实际运行分组 Adam 以核对实现。
4. 每个 PDE 的核心阶段实际新增 30–70 次正式训练，确切数字取决于冻结的验证集选择。同一任务在多个比较间只训练一次。所有原始和新增模型均保留。计划内数值发散留空，涉及不完整配对的推断留空。结果在 revision_runs/{heat,burgers}/evaluation_core.json，原热方程九配置新测试指标在 results_fresh_test_revision/analysis/。原 Burgers 留一法结果在 revision/burgers_leave_one_out.csv。

## 扩展对照
核心实验完成后，如需逐项回应归一化、可学习门控和训练预算意见，可单独提交：
```bash
bash revision/submit.sh extend
```
扩展为每道方程再训练 60 个去归一化或固定门控模型（2 万步）和 40 个长预算模型（从头训练，完整 4 万步余弦调度）。采用原正式模型的学习率，保持原模型作为配对参照。已完成的核心任务读取缓存。结果位于 evaluation_all.json。扩展的范围应在查看其结果前确定，并报告任何未实施的对照。

## 时间、恢复和解释
每个数组批次最多四个并行进程，每个进程四线程、最多两次训练。按历史正式任务 2 万步约 3.3 小时（heat）和 3.5 小时（Burgers），核心实验两道方程合计约 5–8 个连续节点日，为理想并行外推。最后一批空槽、调度、节点速度和评估增加实际日历时间。扩展阶段额外约 10 个节点日。按节点小时计费时，费用约为节点日 × 24 × 小时单价。

作业日志在解压目录 revision-*.out。中断后可单独重提相同数组元素，完整检查点用于恢复；同一阶段输出目录不应同时运行两条提交链。旧 afterok 依赖在上游失败后可能需要取消并重新提交。保留 revision_runs 和 results_fresh_test_revision。

同一设置下 hybrid 与 split 的配对差异衡量更换输出投影更新规则后的经验差异。若区间较宽或包含零，报告差值与区间，并说明现有精度能否区分两者。若交互反转，报告在哪道方程和哪个设置下反转。去归一化、固定门控、长预算未实施时，相应机制和预算外推仍待检验。
